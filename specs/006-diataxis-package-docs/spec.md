# diataxis — lessons from restructuring real package docs

**Feature Branch**: `claude/diataxis-skill-package-docs-f706ee`

**Created**: 2026-11-24

**Status**: Implemented.

**Input**: fold into the `diataxis` skill what two restructured Python package doc sets taught —
one a units library whose docs the skill itself reorganised and which then needed a year of
follow-up fixes, one a statistics package built to a written docs contract from the start.

Only the full Spec Kit flow's first record is here. The change is skill prose plus one test; it
has no data model, no contracts and no build sequence worth writing down.

## What the skill was missing

The four modes and the moves held up. Everything the two doc sets added sits in the layer
*underneath* the modes, which the skill covered thinly for a library whose subject matter is
itself technical.

1. **Explanation wants two sections, not one.** "Why it is built this way" and "what the code
   actually computes" are different reading jobs. One section holding both produces a page that
   alternates friendly paragraphs with derivations. The two sections differ in more than depth:
   the ideas section is *read in order* and carries no code, the mechanism section is consulted
   and carries the mathematics. Neither is a fifth mode.
2. **Reference needs four pages the skill did not name.** A glossary with one word per meaning; a
   notation page with one symbol per meaning whose third column is the name the code uses; a
   warnings-and-errors page keyed by the exact message, each entry shaped When / Cause / Fix; and
   a defaults-and-constants page generated from the source. Each exists because some other page
   would otherwise own a fact it cannot keep.
3. **A warning the code emits and the docs never mention is a reference gap** that no link
   checker, docs build or API generator finds. Its companion is a troubleshooting how-to, which
   needs a second list for the mistakes that bias a result without emitting anything — those
   have no text to key on.
4. **A field dimension, when several communities invented the same subject independently.** One
   page per community, and a landing page carrying a vocabulary crosswalk and a methods table.
   The discipline that makes it survive is that a community's own words appear only on its own
   page. Claims about other people's software get a survey date and a note that releases of your
   own project do not refresh them.
5. **A package family is a dimension, not a section.** Satellite packages keep their own docs
   trees, surfaced as a nav group beside the four modes; the core's four sections document the
   core. A satellite's tree is a doorway, not a doc set, and a satellite with four mode folders
   holding one page each has four stubs.
6. **Design records get a home and no citations.** User pages and docstrings never cite a spec,
   a plan or a decision number; the reason for a design belongs in its issue or pull request and
   in a comment beside the code.
7. **A how-to index can be the product's pipeline**, numbered, when the product has one dominant
   workflow. A guide that fits nowhere in the numbered steps is a guide to question.
8. **A number on a page is a measurement and needs a source.** Every timing, speedup, accuracy
   or chosen threshold comes from a snippet something executes, or from a script whose page names
   the script, its options and the date. This refines the skill's existing rule that verification
   claims must not ship in files: a *provenance* line is a fact about the number and does ship;
   the claim that you personally ran something stays in the summary.
9. **A figure generated by running the product** is the strongest element an orientation page can
   carry, because the docs build fails when the API it calls changes.

## The finding that contradicted the skill

The skill capped `start/` at "three pages, four if an install page is earned, and no more". A
doc set in production has five, and the fifth earns its place: a numbered list of what the
software promises about its answers, every item linking to the page that owns the fact. For a
project whose claim on a reader is the quality of its results rather than a feature list, that
is the page the adoption decision turns on, and no mode will host it. The cap is now five, with
every page past the third argued for in the summary.

## One lesson about the restructure itself

A restructure that dissolves a directory leaves every path under it a redirect target, and a
leftover source file at one of those paths is built as a page and shadows its own redirect. On a
machine that built the docs before the move the leftover is usually a generated artifact nobody
tracks — a `.ipynb` jupytext wrote beside a moved `.md`, since `.ipynb` is normally a
`source_suffix`. CI never sees it, because CI checks out clean, which is why the fix belongs in
the repository: exclude the dissolved tree in the same commit as the move, since the stale files
are untracked and deleting the tracked ones does not reach them.

The two stacks behave differently, and both behaviours were measured rather than assumed:

| | Sphinx + rediraffe | Zensical |
| --- | --- | --- |
| Leftover at a **redirect's** old path | `WARNING: (broken) <old>.html redirects to <new>.html but <old>.html already exists!` — fails only under `-W` | `RuntimeError: redirect output '<old>/index.html' collides with a page` — exits 1 with or without `--strict` |
| Leftover at an **unmapped** path | fails under `-W`: "document isn't included in any toctree" | built and published silently; `--strict` with both validation keys set to `error` reports "No issues found" |
| The setting that excludes it | `exclude_patterns = ["guides/**"]` | `exclude_docs` in `[project]`, a multiline string of patterns |

So Zensical cannot ship a shadowed redirect but will happily publish an orphan, and Sphinx is
the other way round only in degree: both of its cases are warnings, and a project that does not
build with `-W` gets neither. `references/sphinx-myst.md` and `references/zensical.md` document
their own halves, and `tests/skills/diataxis/run.sh` checks all six cells — including that
Zensical's collision message is still the one the reference quotes, and that a silently
published orphan is still silently published.
