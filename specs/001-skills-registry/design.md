# Skills registry — agreed design (input to /speckit-plan)

Agreed with the author on 2026-10-21/22, section by section.

## Context

- Today: local skills `<skill>/` (SKILL.md, card.json) in nstarman/skills; `check-cards.yml`
  validates cards; the website's `scripts/collect-skills.mjs` (weekly `refresh-skills.yml`) reads
  `*/card.json` through the GitHub API and writes `config/skills.json` for /tools/.
- Skills elsewhere: `nstarman/quax` `skills/quax`; `GalacticDynamics/unxt` `skills/unxt`
  (nstarman/unxt is a fork without it); `nstarman/figkit` `skills/figkit`, `skills/figkit-upgrade`.
- Approaches considered: registry + generated outputs (chosen); vendored copies (rejected:
  duplication and drift); git submodules (rejected: whole repos, friction, invisible to the API
  collector). Descriptions live in the registry entry for now; deferring to an upstream `card.json`
  may come later.

## 1. Layout and registry format

```
<skill>/                         local skills, unchanged
registry/<name>.json             one per external skill
index.json                       generated
.claude-plugin/marketplace.json  generated
scripts/build_index.py           generator + validator (stdlib Python)
README.md                        skill table + install section generated between markers
```

```json
{ "name": "unxt", "description": "…",
  "source": { "repo": "GalacticDynamics/unxt", "path": "skills/unxt", "ref": "main" } }
```

Exactly these keys. `name` = file stem = `SKILL.md` name at ref; unique across local + registry.
`ref` is a tag (versioned skills) or a branch (tracking). Initial entries: quax (`nstarman/quax`,
`skills/quax`, `main`); unxt (`GalacticDynamics/unxt`, `skills/unxt`, `main`); figkit and
figkit-upgrade (`nstarman/figkit`, `skills/<name>`, `v0.2.0`). Repo-internal `.github/skills/*`
are not registered.

## 2. Generated outputs and validation

`index.json`:

```json
{ "$comment": "Generated by scripts/build_index.py from */card.json and registry/*.json. Do not edit.",
  "schema": 1, "marketplace": "nstarman-skills",
  "skills": [ { "name": "unxt", "description": "…", "origin": "external",
                "href": "https://github.com/GalacticDynamics/unxt/tree/main/skills/unxt",
                "source": { "repo": "GalacticDynamics/unxt", "path": "skills/unxt", "ref": "main" },
                "install": "unxt@nstarman-skills",
                "zip": "https://github.com/nstarman/skills/releases/latest/download/unxt.zip" } ] }
```

Sorted by name; local `href` = this repo's folder at `main`, local `source` = this repo, `ref` main.

`.claude-plugin/marketplace.json`: name `nstarman-skills`, owner Nathaniel Starkman; one plugin per
skill, plugin name = skill name (skills appear as `/<name>:<name>`); local skills sourced from this
repo, external via `git-subdir` (`url` = repo, `path`, `ref`); the entry is the manifest (no
plugin.json needed). **Spike first**: which form makes a single skill folder a plugin —
`"skills": ["./"]` on the folder itself, or the parent folder with `"skills": ["./<name>"]` —
verified with `claude plugin validate` and a real install of one local and one external skill.

README: table (name, description, from) and install section regenerated between marker comments.

Validation (one workflow replacing `check-cards.yml`, on PR and push): exact keys and non-empty
strings for cards and entries; unique names; local `SKILL.md` name = folder; external `SKILL.md`
fetched at repo/path/ref via the API, name must match; frontmatter limits (name `[a-z0-9-]{1,64}`,
description ≤ 1024 chars; YAML block scalars `>`/`|` parsed); freshness (`build_index.py --check`);
`claude plugin validate .` with the Claude Code CLI installed in CI. Weekly `bump-refs` job:
tag-pinned entries → latest release tag of their repo → one PR updating refs and regenerating.

## 3. Website change (nstarman/nstarman.github.io, separate PR, after this ships)

`scripts/collect-skills.mjs` reads `index.json` (respecting `SKILLS_REF`) instead of scanning
folders; writes `config/skills.json` with `{name, description, href}` plus optional `from`
(external repo); throws and writes nothing on missing/malformed input. /tools/ shows "from
<repo>" for external skills and one "install all" pointer to the README. `refresh-skills.yml`
unchanged (weekly + manual). No cross-repo trigger and no new secrets.

## 4. Zips and releases

Zip = one top-level folder `<name>/` with `SKILL.md` and its resources, without `card.json`;
external skills fetched at their ref. `release.yml`: on pushes to `main` touching skills or the
registry, weekly, and manual; build all zips, compare content hashes with the latest release's,
publish a new release tagged `vYYYY.MM.DD` (suffix `.N` if repeated that day) only when anything
changed. `releases/latest/download/<name>.zip` is the stable link in `index.json`. Only
`GITHUB_TOKEN` with `contents: write`. README install: Claude Code (`/plugin marketplace add
nstarman/skills`, `/plugin install <name>@nstarman-skills`), claude.ai (download zip, upload),
by hand (copy the folder).
