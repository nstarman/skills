# nstarman/skills Constitution

nstarman/skills is the central registry and clearinghouse for the agent skills Nathaniel Starkman
publishes: the place they are registered, listed, validated and installed from, wherever each
skill's files live.

## Core Principles

### I. One source per skill

- Every published skill is registered exactly once: a local folder `<skill>/` with its `SKILL.md`,
  or a registry entry `registry/<name>.json` pointing to the skill's folder in its own repository
  at a tag or branch.
- Skills that live in another repository MUST NOT be copied into this one. The registry points;
  the source repository owns the content.
- Skill names are unique across local folders and registry entries.

### II. Generated outputs are never hand-edited

- `index.json`, `.claude-plugin/marketplace.json` and the README's skill table are generated by
  `scripts/build_index.py` from the local folders and the registry, and committed.
- CI MUST fail when a committed output differs from what the script generates.

### III. Validated against the source

- Every entry is checked where its files actually are: a local folder has a `SKILL.md` whose
  `name` equals the folder name; a registry entry's `SKILL.md` is fetched from its repository, path
  and ref, and its `name` must equal the entry's.
- `SKILL.md` frontmatter MUST meet the strictest install target (claude.ai): `name` of lowercase
  letters, digits and hyphens, at most 64 characters; `description` at most 1024 characters.
- A broken entry fails CI here, never on someone's install or on the website.

### IV. Installable three ways from the same content

- Every skill is installable from the Claude Code marketplace (`nstarman-skills`), as a zip for
  claude.ai from the latest release, and by copying its folder. All three come from the same
  source at the same ref.

### V. `index.json` is a public contract

- The website and other consumers read `index.json`. Its schema carries a version; a change that
  removes or renames a field, or changes a field's meaning, bumps that version and is announced in
  `AGENTS.md`. Adding an optional field does not.

### VI. Small and dependency-free

- Scripts are standard-library Python 3 or Bash. Workflows use only the repository's own
  `GITHUB_TOKEN`; no new secrets.

### VII. Published skills only

- Only skills meant for others to install are registered. A repository's internal tooling skills
  (such as `.github/skills/code-review`) are not.

## Repository Rules

- Squash merges only. Each local skill also has a `card.json` (name, description) — the card
  format the registry entries share.
- Agent guidance lives in `AGENTS.md`; this constitution overrides it where they differ.

## Governance

- This constitution overrides other practices here. Specs and plans include a constitution check;
  deviations are justified in the plan's complexity tracking.
- Amendments are made by pull request with a version bump: MAJOR for removing or redefining a
  principle, MINOR for adding or materially expanding one, PATCH for wording.
