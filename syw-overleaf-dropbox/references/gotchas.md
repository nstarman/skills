# Gotchas, with causes

Each entry is a symptom, why it happens, and what to do.

## Builds that stall or hang

- **Idle for many minutes right after `Syncing file with Zenodo ... cache`, no CPU, no child
  process.** `SANDBOX_TOKEN` (or the Zenodo token) is not set; the sync fails and then waits
  forever. Interrupt (`kill -INT <pid>`) and rerun with the token. Say so in the project README.
- **Looks hung at `Updating checkpoint dependencies` for an hour or more.** Not a deadlock:
  SYW walks each output's upstream dependencies recursively and runs `git` per edge. With
  dozens of `\variable{}` outputs it takes hours. Memoize
  `showyourwork.config.expand_dependency_directories` (for example with
  `functools.lru_cache`) at the top of the `Snakefile`.
- **A build that never starts.** The password-manager CLI is blocked on a locked app:
  `op read` waits silently. Unlock the app and retry. Check that `op` is using the intended
  account (`--account <domain>` or `OP_ACCOUNT`).
- **`Overleaf credential OVERLEAF_TOKEN not found` although it was passed inline.** `op read`
  timed out ("authorization timeout") and returned an empty string; SYW then skips the pull
  and push and still exits 0. Read tokens into variables and check they are non-empty first.
- **A cached rule fails with a network error and its output file disappears.** Snakemake
  deletes outputs of failed jobs, so a flaky connection can remove cached arrays that other
  scripts import. Check connectivity first (`curl` the Zenodo host); restore the previous
  copy from `.showyourwork/cache/` if you must keep working offline; rerun when the network is
  back.
- **A leftover process wedges the next run.** A killed rule can leave a `uv` wrapper alive.
  Clear only your own processes, never other sessions' or the user's other projects'.

## Platform quirks (macOS)

- **`No module named '<package>'`.** macOS can keep re-setting the `hidden` flag on
  `_`-prefixed files in `.venv`, and Python skips hidden `.pth` files, so the editable
  install fails. Build with `PYTHONPATH=src` and `--conda-not-block-search-path-envvars`
  (Snakemake otherwise blocks `PYTHONPATH` in conda jobs).
- **`Bad CPU type in executable ... cbc`.** No Rosetta on Apple Silicon: add
  `--scheduler greedy`.
- **Commit signing fails with `1Password: failed to fill whole buffer`.** Git is signing
  through the password manager's SSH agent and the app is locked or not offering its agent.
  Unlock it and approve. Do not turn signing off to get around it without asking.
- **Moved the project folder.** `.venv` and conda envs are path-specific; expect a rebuild.

## Overleaf and the Dropbox mirror

- **`File figures/...pdf not found` / `output/...tex not found` in an Overleaf compile.** The
  build has not pushed yet (or failed before pushing). Figures and numbers only arrive at the
  end of a build. Waiting for the build, or running one, fixes it. Pushing a single folder
  with the SYW Python API while a build is running risks colliding on the git clone.
- **Mirror and repo checksums differ right after a push.** Dropbox sync lag. Recheck after a
  few seconds before assuming the push failed.
- **The pull refuses to overwrite `ms.tex`.** The repo copy has a commit that is not a
  `[showyourwork]` sync commit. Look at `git log -- src/tex/ms.tex` and reconcile on purpose;
  do not force.
- **Edits to `src/tex/ms.tex` vanish.** The pull overwrote them. Edit the mirror.
- **Undefined citations and references in the first LaTeX pass.** Normal when a figure or
  `.bbl` is missing; fix the missing file first, then recompile twice.

## Silent non-builds

- **Build exits 0 and prints nothing after the Zenodo lines.** Nothing needed to run. This
  happens when a figure PDF you generated by hand is newer than its script. Delete the PDF
  and rebuild.
- **A figure script edit that has no effect on the pushed figure.** Same cause.
- **The build succeeds but never pushes to Overleaf** (no `Pushing changes to Overleaf` in the
  log). SYW pushes from Snakemake's `onsuccess` handler, which is skipped when there is nothing
  to do, for example after an earlier run built everything but failed to sync. Delete `ms.pdf`
  and build again.

## Things that look like SYW bugs but are not

- **A number or figure never gets generated.** SYW only builds what `ms.tex` references: cite
  numbers with `\variable{...}` (not a custom macro that `\input`s the file), and include a
  figure with `\includegraphics` of the exact path a `Snakefile` rule produces. See SKILL.md,
  "What SYW builds is decided by what `ms.tex` references".

## CI

- **`MissingInputException` for a values file.** Some rule lists a derived file as an input,
  but no rule produces it (derived data is usually gitignored, so a clean checkout lacks it).
  Add a rule whose output is that file.
- **Stale generated-variable test.** A test that compares `src/tex/output/**` with the
  code fails after the numbers change until a build regenerates them.
- **Fingerprint test fails after editing the settings file.** See "What invalidates caches"
  in `build.md`.
- **CI runs a `cache: True` rule for hours.** `zenodo.yml` has no Sandbox DOI, so SYW does not
  treat the rule as cached on CI and `run_cache_rules_on_ci: false` never applies. Create the
  draft (`showyourwork cache create`) and let a local build upload before pushing.
- **`FileNotFoundError` in `showyourwork cache restore`, on a figure.** A cached rule's output is
  a symlink into `.showyourwork/cache`. Under `src/tex/figures` the GitHub Actions article cache
  saves the link without its target, and the next run crashes on it. Write cached outputs under
  `src/data/` and copy them into `src/tex/figures/` with a plain `cp` rule; bump the action's
  `article-cache-number` to drop the saved cache.
- **A figure CI pushed to Overleaf has a different size from the local one.** A script that
  measures text in pixels (`fig.canvas.draw()`, `get_window_extent()`) before
  `bbox_inches="tight"` depends on the DPI, and matplotlib's default backend differs: `macosx`
  on a Retina Mac draws at 200 dpi, Agg on CI at 100. Pin it in the script:
  `matplotlib.use("agg")` and `plt.figure(..., dpi=200)`. Check with `pdfinfo` (page size).
- **Pytest hangs or starts a long computation.** `--doctest-modules` over `src/` imports every
  figure script, which runs it. Point `testpaths` at the package and `tests/` only.
